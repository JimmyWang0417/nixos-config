# 官方客户端与终端工具维护设计

用户要求保留钉钉和百度网盘官方客户端，不使用 Flatpak。图形文本和 Markdown 默认应用保留 Kate；系统终端 EDITOR 设置为已经安装的 Neovim。

## 应用配方

钉钉使用官方 Linux 下载选择器提供的 9.0.0.261118001，固定负载 URL 和摘要，复用现有 NUR 的 Qt/Xcb、Fcitx 与屏幕共享桥接包装。官方仍称 Linux 版为测试预览；负载依然携带 OpenSSL 1.1.1g，保留准确包名的风险例外和说明，不以升级或隔离掩盖旧库问题。

百度网盘官方 Linux 版本仍为 8.9.7。旧 NUR 配方为了 GTKmm2 导入另一套旧 nixpkgs，改为私有 GTKmm2 兼容配方，用当前全局 unstable 工具链和依赖构建。保留官方负载、FHS、托盘、Fcitx 和必要启动参数，通过静态 ELF 解析检查真实依赖，不启动已登录客户端。

## 终端配置

Neovim 保留主题、Coc、插件与键位，按格式化、构建、运行、通用进程处理拆分。F3 仅格式化缓冲区，F5 构建或检查语法，F6 运行，F7 成功检查后运行。命令采用参数列表，覆盖未保存文件、特殊字符路径和失败行为。

Ranger 保留 Miller、图标和键位，统一调用官方 7zz；预览依赖仅放进自身包装器，限制自动预览大小与耗时。图片协议依据锁定的 Konsole 和 Ranger 能力选择 Sixel，部署后的实际显示仍需确认。已有工作区的 7zz 修改先备份并纳入隔离分支，不丢弃外部工作。

Node/npm 独立管理配置、缓存、全局软件和历史四个 XDG 路径，保留 HOME。迁移仅处理目标缺失且可安全原子移动的状态，冲突、链接、跨盘和活跃进程情况保留原数据。私有 npmrc 不进入 Nix store 或仓库。

## 验证与发布

应用配方、NixOS/Home Manager 集成、运行时辅助程序与测试各有明确边界。实际构建针对性的行为检查，运行配置求值与静态检查，随后刷新软件审计。用户额外授权的本机 Coc 安装与 Node/npm 迁移单独备份验证；不在当前 Manjaro 激活 NixOS、不改引导或分区。整合工作区后提交上传，核实远端提交与 CI。
